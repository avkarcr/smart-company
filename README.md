# Smart Company

Локальное Python-приложение для исследования акций российского рынка. Минималистичная карточка объединяет технические сигналы, проверяемую отчетность, события, управление компанией и PDF-снимок.

**Статус: первая рабочая версия, не завершенная автоматическая аналитическая система.** Автоматически загружаются справочник и свечи МОЕХ, заголовки RSS. Фундаментальные показатели, состав совета и планы пока вносятся и проверяются пользователем. Приложение не торгует и не подключается к брокеру.

## Запуск на Ubuntu

```bash
git clone https://github.com/avkarcr/smart-company.git
cd smart-company
git switch feat/company-research
sudo apt install python3-venv fonts-dejavu-core
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
smart-company
```

Откройте http://127.0.0.1:8765 . Python 3.11+; проверено на Python 3.12. Другой порт: `smart-company --port 8787`.

При запуске справочник МОЕХ обновляется; при сбое используется сохраненная копия с предупреждением. Первая загрузка зависит от сети. Пустая база при недоступной МОЕХ не заменяется вымышленными компаниями.

Данные сохраняются в `~/.local/share/smart-company`. Можно изменить каталог переменной `SMART_COMPANY_DATA`. Резервная копия — копия этого каталога при остановленном приложении. Для PDF нужен шрифт с кириллицей DejaVu Sans; альтернативный TTF задается через `SMART_COMPANY_FONT`.

## Что работает

- Поиск по названию/тикеру среди торгуемых обыкновенных и привилегированных акций (фонды, облигации и расписки не включаются).
- Справочник с пагинацией ISS, выбор основной торговой площадки, до 800 календарных дней дневных свечей; текущая сессия исключается.
- 21 индикатор: SMA 20/50/100/200; EMA 12/26/50/200; MACD; Tenkan/Kijun; RSI; Stochastic; Williams %R; CCI; ROC; Momentum; Bollinger; Keltner; OBV; CMF; MFI.
- Настраиваемые порог (по умолчанию 80%), минимальное покрытие, веса групп и каждого индикатора. Вес 0 отключает инструмент.
- Форма двух официальных отчетов, сравнение сопоставимых периодов, источники и страницы, отметки проверки. Стратегия, M&A и директора — структурированное досье.
- События Интерфакса из доступной RSS-ленты: заголовок, дата, ссылка, тематические метки. Полные статьи не копируются. Нет гарантии полноты ленты.
- Адаптер ссылок e-disclosure для известного ID эмитента. При блокировке/изменении HTML — явный статус и ссылка на раздел МСФО. Начальные проверенные ID: Сбербанк 3043, ЛУКОЙЛ 17. Другие задаются в досье.
- Отраслевая цветовая маркировка и структурные факторы отрасли. Исходная классификация неполна и редактируется.
- P/E, P/B, P/S, EV/EBITDA и Net debt/EBITDA, когда достаточно проверенных данных. Капитализация всех классов акций вводится вручную в млн валюты отчета с датой.
- PDF со всеми аналитическими разделами, правилами индикаторов, настройками и ссылками из сохраненного снимка.
- Локальный сервер привязан к 127.0.0.1; проверка Host, защита записей CSRF-токеном, экранирование HTML, отсутствие удаленных JS/CSS.

## Ручная загрузка отчетов

В карточке компании, в разделе отчетности, выберите **«Добавить файлы отчетов»**. Можно выбрать до 10 файлов одновременно: PDF с текстовым слоем, DOCX или TXT, до 20 МБ каждый. После загрузки отображаются имя файла, тип (годовой / квартальный или промежуточный), отчетный период, дата загрузки и статус актуальности. Оригиналы можно скачать.

Файлы сохраняются отдельно для каждого тикера в `~/.local/share/smart-company/reports/`; индекс хранится рядом в `uploads-ТИКЕР.json`. Переключение компании и перезапуск приложения их не удаляют. Бэкап должен включать весь каталог данных. Один и тот же файл у одной компании не дублируется (SHA-256); у разных компаний допускается.

Период и тип распознаются из первых 8 страниц PDF или начала DOCX/TXT по русским и английским формулировкам. Поддерживаются год, квартал, полугодие и 9 месяцев. Если текст не извлечен, найден только шаблон в имени файла, есть конфликт с именем или будущая дата — отображается «Нужно уточнить». В раскрывающемся блоке можно подтвердить или исправить период. Сканы без текстового слоя сохраняются, но OCR пока не выполняется. Распознавание периода не подтверждает принадлежность документа компании: проверьте выбранную карточку перед загрузкой.

Давность считается **от конца отчетного периода**, а не от дня загрузки: больше 450 дней для годовых и 210 дней для промежуточных отчетов. У каждого файла есть статус; если последний распознанный отчет устарел, список показывает общее предупреждение. Неопределенный период не считается свежим. Это прозрачное напоминание, не утверждение о нормативном сроке публикации или наличии более нового отчета. Метки пересчитываются при открытии карточки/списка, а не таймером в открытой вкладке.

При недоступности отчетов Интерфакса отображается: **«Надо загрузить отчет вручную.»** Загруженные файлы доступны независимо от ошибки источника, включены списком в PDF-карточку. Сами финансовые показатели из файлов автоматически не переносятся в фундаментальную модель: проверяемый ввод показателей в досье сохранен.

## Как начать исследование

1. Найдите компанию и откройте карточку. «Ждать» до заполнения официальных данных — ожидаемое поведение.
2. В «Настройках анализа» задайте порог и веса. Взвешенный режим нормирует индикаторы внутри группы: множество похожих средних не получает автоматического преимущества.
3. Откройте «Досье и отчеты». Укажите два последних доступных отчета, ссылки, страницы, стандарты, периоды и показатели **в миллионах**, в одной валюте. Не смешивайте консолидированные МСФО с отдельными РСБУ.
4. Если два последних отчета несопоставимы (например 6 и 12 месяцев), сравнение блокируется. Автоматического TTM и извлечения сравнительного периода из примечаний пока нет.
5. Проверьте стратегию, M&A и состав совета в официальных источниках. Заполните структуры из подсказок в форме. Риск стратегии блокирует позитивный итоговый сигнал.
6. После обновления сохраните PDF. Он использует сохраненный снимок карточки, не запускает повторный сбор.

## Методика и ограничения

Итог «покупать/продавать» требует согласия технического и фундаментального сигналов, достаточного покрытия и отсутствия проблем свежести рыночных данных. Правила — прозрачные эвристики, **не проверенная торговая стратегия**. Порог голосов, даже 80–100%, не означает вероятность результата. Инструменты коррелированы.

Фундаментальная эвристика: рост выручки и чистой прибыли более 5% при положительном капитале — buy; падение прибыли более 20%, убыток или неположительный капитал — sell; иначе wait. Нужны подтвержденные последние отчеты и качественный обзор. Отчеты старше 400 дней блокируются. Рост между выбранными сопоставимыми периодами не обязательно годовой. ROE считается по среднему капиталу за период и не годовой, если период короче года.

Ценовой диапазон ±2 ATR показывает масштаб дневной волатильности. Это **не целевая цена**, не доверительный интервал и не обещание цены через месяц. DCF, сценарии оценки и калиброванный прогноз еще не реализованы. История не корректируется на дивиденды/сплиты; соответствующие гэпы требуют отдельной проверки.

LinkedIn используется только как ссылка на профиль; универсального рейтинга директоров приложение не предполагает. Альтернативы: официальный сайт эмитента, РБК «Персоны», TAdviser. Сходство ФИО не подтверждает личность.

### Еще не реализовано

- Автоматическое сопоставление всех эмитентов с e-disclosure, загрузка и извлечение таблиц из PDF/XLS/OCR; подтверждение того, что найдены именно последние два отчета.
- Автоматические биографии и обновление состава совета директоров.
- Семантический разбор стратегии/M&A с привязкой каждого вывода к странице официального отчета.
- Полноценные актуальные отраслевые обзоры, сравнение мультипликаторов с аналогами, DCF/целевая цена.
- Дополнительные новостные источники и лицензированные архивы. Адаптер e-disclosure зависит от доступности сайта и его HTML; это не официальный API.
- Бэктест, учет корпоративных действий, портфельного риска, комиссий и ликвидности.

Не обходите CAPTCHA/платный доступ источников. Для надежного промышленного покрытия потребуется разрешенный канал поставки данных. Следующий этап — автоматизация отчетности, а не добавление новых индикаторов.

## Проверки

```bash
python -m unittest discover -s tests -v
# Браузерные сценарии на синтетических данных:
pip install playwright
python -m playwright install chromium
python tests/browser_scenarios.py
```

GitHub Actions запускает расчетные, HTTP и браузерные проверки; скриншоты доступны в артефакте `ui-screenshots`. Браузерные тесты проверяют поиск, карточку, изменение порога, досье, PDF, отсутствие горизонтального переполнения на ширине 390 px и ошибок JavaScript. Это инженерная проверка интерфейса, не исследование UX с пользователями.

Источники и принципы интерфейса: [docs/design-and-sources.md](docs/design-and-sources.md).
